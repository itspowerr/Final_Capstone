2. COMPLETE DATA FLOW
================================================================================

A. FREELANCER SUBMITS DELIVERABLE (HAPPY PATH)
===============================================

  Freelancer selects file + writes notes on Submit modal
         |
         v
  1. Frontend (MyContracts.js)
     - Reads file bytes from <input type="file">
     - Calls:  import { uploadFile } from '../../services/ipfs';
                const result = await uploadFile(file);
     - This POSTs file as multipart/form-data to:
           POST /api/ipfs/upload
           Headers: { Content-Type: multipart/form-data, Authorization: Bearer <token> }
     - Backend router (ipfs.py) receives the UploadFile
         |
         v
  2. Backend (routers/ipfs.py -> services/ipfs_service.py)
     - Reads all bytes from UploadFile
     - Calls ipfs_service.upload_file_bytes(contents, filename)
         |
         v
  3. ipfs_service.py
     - Writes bytes to a tempfile
     - Opens tempfile as BinaryIO
     - POSTs to Kubo API:  POST http://ipfs:5001/api/v0/add
       (multipart/form-data with file attached)
     - Kubo returns JSON:  { "Hash": "QmX...", "Size": 12345 }
         |
         v
  4. ipfs_service.py returns  { "cid": "QmX...", "size": 12345 }
         |
         v
  5. ipfs.py router:
     - Calls ipfs_service.pin_file(cid) -> POST /api/v0/pin/add?arg=QmX...
       (ensures IPFS node keeps the data pinned)
     - Guesses mime type from filename
     - Returns IPFSUploadResponse(cid, size, mime_type)
         |
         v
  6. Frontend receives:  { cid: "QmX...", size: 12345, mime_type: "application/pdf" }
     - Now calls:  api.post(`/contracts/${contractId}/milestones/${index}/submit`,
                            { deliverable_cid: cid, submission_notes: notes })
         |
         v
  7. Backend (contracts.py / contract_service.py)
     - Stores deliverable_cid + submission_notes in contract_milestones row
     - Returns updated MilestoneResponse
         |
         v
  8. Frontend updates local state, shows toast "Deliverable submitted!"

3. DOCKER IPFS SERVICE CONFIGURATION
================================================================================

docker-compose.yml addition:

  ipfs:
    image: ipfs/kubo:v0.28.0
    container_name: freeledger-ipfs
    ports:
      - "5001:5001"    # API (backend uses this)
      - "8080:8080"    # Gateway (frontend uses this)
    volumes:
      - ipfs_data:/data/ipfs
      - ./docker/ipfs/config.sh:/container-init.d/config.sh
    environment:
      IPFS_PROFILE: server
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "curl -s http://localhost:5001/api/v0/version > /dev/null 2>&1 || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 3
    deploy:
      resources:
        limits:
          memory: 1G

docker/ipfs/config.sh:

  #!/bin/sh
  ipfs config --json API.HTTPHeaders.Access-Control-Allow-Origin '["*"]'
  ipfs config --json API.HTTPHeaders.Access-Control-Allow-Methods '["PUT", "POST", "GET"]'

4. BACKEND CONFIG CHANGES
================================================================================

config.py — new settings to add to Settings class:

  ipfs_api_url: str = "http://127.0.0.1:5001"
  repin_interval_seconds: int = 21600          # 6 hours
  ipfs_monitor_interval: int = 30              # seconds between health checks
  ipfs_degraded_threshold: int = 2
  ipfs_down_threshold: int = 4

Note: In docker-compose, the backend uses "http://ipfs:5001" (Docker DNS).
When running locally with uvicorn, it uses "http://127.0.0.1:5001".
The .env file controls which hostname is used.


================================================================================
5. KEY DESIGN DECISIONS
================================================================================

  +--------------------------------------+----------------------------------------------------+
  | Decision                             | Rationale                                          |
  +--------------------------------------+----------------------------------------------------+
  | Backend talks to Kubo API (5001)     | API supports pinning; gateway (8080) is read-only  |
  | Frontend access via gateway (8080)   | Simple URL, no auth needed for public IPFS content |
  | Files always pinned on upload        | Prevents GC from removing deliverables             |
  | httpx.AsyncClient for IPFS calls     | Non-blocking, matches FastAPI async model          |
  | Repin runs every 6 hours             | Keeps CIDs alive across Kubo restarts              |
  | IPFS monitor runs every 30 seconds   | Quick detection of IPFS node failure               |
  | Existing uploads.py router stays     | Local disk uploads remain separate from IPFS       |
  +--------------------------------------+----------------------------------------------------+
